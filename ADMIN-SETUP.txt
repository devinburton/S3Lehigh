S3 LEHIGH PRIVATE DIRECTORY SETUP

Deploy only AFTER applying supabase/private-directory.sql successfully.
1. In the SQL file replace REPLACE_WITH_EXISTING_ADMIN_EMAIL with a verified existing Supabase Auth administrator email. Add a second email to the array for a second administrator if needed.
2. Run the complete SQL in Supabase SQL Editor. It is transactional: missing administrator accounts stop all changes. Contractor rows are preserved. Existing non-admin accounts become pending; approve any intended members from the dashboard.
3. Supabase Authentication: enable email signup and email confirmation. Add https://s3lehigh.com/ to the allowed redirect URLs and use it as the Site URL.
4. Deploy the website changes. Sign in at https://s3lehigh.com/admin/ to approve or revoke membership requests. Approved members can only read contractors; approved administrators can manage contractors and member status. Browser users cannot change roles, grant themselves access, or edit member profiles.
5. Test anonymous, pending, approved, revoked, and administrator accounts before announcing access. Anonymous and pending accounts must not be able to read Contractors over the API. Approved members must not be able to change Contractors or membership status.

No contractor contacts or import seeds are bundled in the new pages. There is no public fallback. A revoked member cannot make new database reads; data already viewed or downloaded cannot be recalled. The page checks access again on return to the tab and once per minute.
Email notifications are not configured. Requests appear in the admin dashboard. An administrator email and a server-side email service/webhook are needed for notifications.
Historical contractor data remains in the public GitHub history from earlier versions. Removing data from the current site does not erase previously published copies; review repository visibility and history separately.
